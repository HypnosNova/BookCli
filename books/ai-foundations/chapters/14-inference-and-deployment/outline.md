# 推理、部署与工程优化

## 本章目标

- 采用“实际问题—既有方法的难点—技术机制—适用边界”的叙事顺序，避免核心概念直接从定义起笔。
- 理解训练和推理的差异。
- 掌握 LLM 推理中的延迟、吞吐、KV Cache、batching 等概念。
- 从系统角度认识 AI 应用上线后的工程问题。

## 建议结构

1. 训练与推理的区别
   - 训练更新参数。
   - 推理固定参数生成结果。
   - 成本结构不同。
2. 推理流程
   - 输入 token 化。
   - prefill。
   - decode。
   - streaming 输出。
   - TTFT 和每 token 生成时间。
3. KV Cache
   - 为什么自回归生成可以缓存历史 Key/Value。
   - 上下文越长缓存越大。
   - 显存占用和吞吐的关系。
   - KV Cache 的粗略显存估算。
   - vLLM、TensorRT-LLM、SGLang、TGI、llama.cpp、Ollama 等推理工具。
   - 推理框架对比表。
4. Speculative Decoding
   - 小模型草拟，大模型验证。
   - 适用场景和收益边界。
   - 与 decode 成本和 KV Cache 管理的关系。
5. 服务化部署
   - 单请求延迟。
   - 吞吐。
   - 动态 batching。
   - 限流、超时和重试。
   - API 网关、请求编排、模型队列、GPU 节点和输出处理。
   - 灰度发布和回退。
   - Prefill 和 decode 分离调度。
   - 可观测性指标和自动扩缩。
6. 应用层架构
   - Prompt 模板。
   - RAG。
   - Tool calling。
   - 日志、评估和回放。
   - 把模型擅长的事和系统必须保证的事分开。
7. 成本优化
   - 模型选择。
   - 缓存。
   - 小模型和大模型协同。
   - 离线生成与在线推理。
   - 按请求复杂度选择刚好够用的能力。
   - 上下文裁剪和缓存命中。
   - 用每月 100 万次请求的量级例子说明级联策略成本差异。
8. 端侧与边缘推理
   - 端侧推理的隐私、延迟和离线优势。
   - 量化、小模型和硬件加速。
   - 云端与端侧混合架构。
9. 上线前 Checklist
   - 效果、延迟、吞吐、成本、显存、安全、监控、回退和线上评估。

## 实践任务

- 画出一个 LLM API 服务请求链路。
- 解释 prefill 和 decode 的区别。
- 设计一个降低推理成本的方案。
- 标注链路中影响首 token 时间、总生成时间和 token 成本的环节。
- 用假设 token 数估算不同成本优化策略的相对影响。

## 本章产出

读者应能从应用系统角度理解模型上线，而不只关注模型本身。
