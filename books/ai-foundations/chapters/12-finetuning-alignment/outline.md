# 微调、指令对齐与偏好学习

## 本章目标

- 采用“实际问题—既有方法的难点—技术机制—适用边界”的叙事顺序，避免核心概念直接从定义起笔。
- 理解预训练模型为什么还需要对齐。
- 区分 SFT、RLHF、DPO 等常见方法。
- 知道什么时候需要微调，什么时候更适合 prompt、RAG 或工具调用。

## 建议结构

1. 预训练模型的问题
   - 会续写文本，不一定会遵循指令。
   - 输出风格、格式和安全边界不稳定。
   - 领域知识可能不足或过时。
2. Supervised Fine-Tuning
   - 指令、输入、理想回答。
   - 单轮 instruction/input/output 数据格式。
   - 多轮 messages 数据格式。
   - 用高质量示例让模型学会任务格式。
   - 数据质量比数量更关键。
   - 持续预训练和 SFT 的区别。
   - 灾难性遗忘和缓解方法。
3. 偏好学习
   - 人类偏好数据。
   - 奖励模型。
   - RLHF 的基本流程。
   - SFT 像给范例，RLHF 像用评分系统继续训练。
4. DPO 等直接偏好优化
   - 不显式训练奖励模型的思路。
   - chosen / rejected 样本。
   - 工程上更简单的原因。
5. 对齐与安全边界
   - 对齐不只是听话，也包括拒绝不该做的事。
   - 安全偏好数据和拒答边界。
   - 对齐税：安全性和有用性的取舍。
6. 微调决策
   - prompt 足够时不微调。
   - 需要私有知识时优先考虑 RAG。
   - 需要稳定风格、格式或任务能力时考虑微调。
   - 用决策树区分 prompt、RAG、SFT、DPO/RLHF。
7. LoRA、QLoRA 与全量微调
   - LoRA 冻结基础模型，只训练低秩增量。
   - QLoRA 用量化基础模型降低显存。
   - LoRA、QLoRA、全量微调的选择指南。
8. 微调后如何评估
   - 目标任务、通用能力、格式稳定性和安全边界。
   - 自动评估、人工评估、灰度和回归集。
9. 开源微调的实践路径
   - 选择基础模型和 tokenizer。
   - 准备指令数据和评估集。
   - 使用 Transformers、TRL、LLaMA-Factory、Axolotl 等工具。
   - 从 LoRA 或 QLoRA 开始并做好版本管理。

## 实践任务

- 为客服场景设计 5 条 SFT 数据。
- 判断三个需求分别适合 prompt、RAG 还是微调。
- 设计一条 chosen/rejected 偏好样本。

## 本章产出

读者应能理解对齐不是让模型“更聪明”，而是让模型更符合任务和人类偏好。
