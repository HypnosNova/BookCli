# Embedding 与表征学习

## 本章目标

- 采用“实际问题—既有方法的难点—技术机制—适用边界”的叙事顺序，避免核心概念直接从定义起笔。
- 理解 embedding 是把离散对象映射到连续向量空间。
- 理解 embedding 如何从训练目标和数据关系中学习出来。
- 认识相似度、向量检索和语义空间。
- 理解精确检索、ANN、向量索引和向量数据库的区别。
- 理解 RAG 中 embedding 的离线入库、在线检索、过滤和重排流程。
- 为理解 Transformer 和大语言模型打基础。

## 建议结构

1. 为什么需要向量表示
   - 机器无法直接理解文字、图片、用户和商品。
   - one-hot 表示的稀疏和无语义问题。
   - 用 10 万词表例子解释 one-hot 的局限。
   - embedding 的压缩与语义承载。
   - embedding 维度和成本之间的关系。
2. 文本如何变成 token
   - 原始文本为什么不能直接进入模型。
   - 字符切分、整词切分和子词切分的取舍。
   - BPE 的直觉。
   - WordPiece 和 SentencePiece 的概念区别。
   - tokenization 对多语言、上下文窗口和调用成本的影响。
3. Embedding 是怎么学出来的
   - 训练目标如何决定向量空间。
   - 相似上下文、点击关系、图文匹配如何拉近向量。
   - 不同任务需要不同 embedding。
4. 向量空间直觉
   - 距离和相似度。
   - 余弦相似度。
   - 聚类和近邻。
   - 为什么向量相似不等于一定能回答问题。
5. 词向量与上下文表示
   - 词向量如何从上下文中学习。
   - 相似词靠近。
   - 多义词和上下文表示的挑战。
6. 表征学习
   - 模型中间层为什么可以作为特征。
   - 图像、文本、音频的统一向量表示。
   - CLIP 类模型如何把图文映射到同一空间。
7. 向量检索、向量数据库与 RAG
   - 先从私有知识、海量资料和人工阅读成本解释为什么生成模型还需要检索。
   - 余弦、点积和欧氏距离；精确最近邻与 ANN。
   - 向量索引和向量数据库的职责边界。
   - 从 1975 年 k-d tree、1998 年 LSH、2011 年 PQ、2016 年 HNSW 到现代向量 DBMS 的演进。
   - 为什么向量检索长期存在，却在通用 embedding、RAG 和动态数据管理出现后才进入主流应用开发。
   - 关系型、文档型与向量系统在数据模型、查询谓词和结果语义上的区别与组合。
   - WAL、可变与不可变 segment、异步索引、tombstone 和 compaction。
   - 分片、复制、局部召回、全局 Top-K 合并与读写一致性。
   - pgvector、MongoDB Vector Search、Elasticsearch/OpenSearch、Qdrant、Weaviate、Milvus、Pinecone、Redis 与 Chroma 的定位差异。
   - 关系数据库扩展、搜索引擎、专用数据库、托管服务和本地工具的选型边界。
   - HNSW、IVF 和 PQ 的直觉、代价与参数权衡。
   - 向量、原文、来源、版本、ACL 和 embedding 版本的记录结构。
   - 元数据过滤与多租户权限必须进入检索边界。
   - 稠密向量、关键词和业务规则的混合召回。
   - 双编码器召回与 Cross-Encoder 重排。
   - 切块、稳定 ID、增量更新、删除和索引版本发布。
   - 用真实查询集评估 Recall@k、延迟、内存和过滤后召回。
8. Embedding 在系统中的常见用途
   - 推荐、广告、代码搜索、客服工单和异常检测。
   - embedding 如何帮助系统复用历史经验。

## 实践任务

- 用 embedding 解释“语义搜索”。
- 设计一个文档问答系统中的向量检索流程。
- 比较关键词检索和向量检索的优缺点。
- 准备少量文档，尝试用 embedding 做一次语义检索，观察召回结果。
- 手工设计切块和元数据方案。
- 为一个多租户知识库设计 ACL 过滤和删除传播方案。
- 在精确搜索基线上比较一种 ANN 索引的召回率、延迟和内存。
- 用同一数据集比较两类向量存储，覆盖严格过滤、写后读、删除、节点恢复和成本。

## 本章产出

读者应能理解为什么现代 AI 系统大量围绕向量表示构建，能区分 embedding 模型、向量索引、向量数据库和完整 RAG 链路，并能根据数据模型、查询、可靠性和运维要求设计向量数据库 POC。
