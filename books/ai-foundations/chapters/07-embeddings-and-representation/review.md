# 第7章 审阅记录

## 叙事入口审校（2026-07-29）

- 已检查正文核心概念入口，改为先说明实际任务、失败现象或工程约束，再引出技术机制、正式概念和适用边界。

## 已覆盖内容

- one-hot、静态词向量、上下文表示与表征学习的递进关系。
- tokenization、BPE、WordPiece、SentencePiece 和多语言成本影响。
- 余弦、点积、欧氏距离以及精确最近邻与 ANN 的边界。
- 向量索引和向量数据库的区别；HNSW、IVF、PQ 的直觉与代价。
- 从 k-d tree、LSH、PQ、HNSW 和 Faiss 到 purpose-built vector DBMS 的历史脉络。
- 解释向量能力为何长期隐藏在搜索、推荐和机器学习基础设施中，以及 embedding 与 RAG 如何扩大开发者受众。
- 区分关系型、文档型数据库的数据模型变化与向量检索的相似度查询语义，避免把三者写成简单替代关系。
- 向量数据库的 WAL、segment、索引发布、tombstone、compaction、分片、副本和一致性原理。
- pgvector、MongoDB Vector Search、Elasticsearch/OpenSearch、Qdrant、Weaviate、Milvus、Pinecone、Redis 与 Chroma 的定位对比。
- 过滤时机、写入可见性、删除传播、混合检索、多租户和资源模型的产品差异。
- 从现有系统出发建立候选名单，再以真实查询、更新、故障和成本做 POC 的选型方法。
- 向量记录中的原文、来源、版本、ACL、有效时间和 embedding 版本。
- 元数据过滤、混合检索、双编码器召回、Cross-Encoder 重排。
- 切块、稳定 ID、增量更新、删除传播与索引版本发布。
- 对比学习、InfoNCE 和 hard negative 的训练直觉。

## 本轮审校处理

- 把首次引出 RAG 的段落改为问题驱动：先说明私有知识、资料规模和人工阅读成本，再给出定义。
- 删除脱离数据、硬件和参数条件的固定召回率、延迟与规模阈值。
- 不再把 ANN 写成所有向量数据库的必选项，保留精确搜索作为质量基线。
- 不再把 HNSW 或 IVF/PQ 写成按数据量即可决定的固定答案，改为在真实查询集上比较召回、延迟、内存、构建和更新成本。
- 明确权限过滤必须进入可信检索边界，不能在模型已经看到无权内容后再补做。
- 移除易过时的具体 reranker 产品推荐，保留双编码器与 Cross-Encoder 的稳定原理。
- 产品表按数据库定位和适用边界组织，不写缺少统一测试条件的性能排名或最大规模结论。
- 用官方架构与索引文档核对各产品截至 2026-07-28 的能力，并明确版本变化边界。
- 历史年份与论文归属按 ACM、IEEE、arXiv、SIGMOD 和 VLDB 原始记录复核，不把早期 ANN 算法直接称为完整向量数据库。

## 后续维护注意事项

- 新增数据库或模型名称时标注版本与审校日期，避免把产品清单写成排行榜。
- 所有性能数字必须同时给出数据集、维度、索引参数、硬件和指标定义。
- embedding 模型升级时，应同时讨论索引重建、双版本评测和删除一致性。
