# 大语言模型如何工作

## 本章目标

- 采用“实际问题—既有方法的难点—技术机制—适用边界”的叙事顺序，避免核心概念直接从定义起笔。
- 从 Transformer 过渡到大语言模型。
- 理解预训练、上下文窗口、token 预测和涌现能力。
- 认识 LLM 能做什么、不能做什么。
- 理解 RAG 的离线知识链路、在线检索链路、证据组装与引用边界。

## 建议结构

1. 语言模型的目标
   - 给定上下文预测下一个 token。
   - 概率分布而不是唯一答案。
   - 用完整句子走一遍“预测、选择、追加、再预测”的生成循环。
   - 采样、temperature、top-p。
2. 采样参数如何影响输出
   - temperature 控制随机性。
   - top-p 控制候选集合。
   - top-k 与 top-p 的区别。
   - 稳定任务和创意任务的参数取舍。
3. 预训练
   - 海量文本语料。
   - 自监督目标。
   - scale 带来的能力变化。
   - 参数量、数据量和计算量分别意味着什么。
   - 不同规模模型的数量级直觉。
   - 涌现能力的直觉和边界。
4. 上下文窗口
   - prompt 如何进入模型。
   - 上下文长度限制。
   - 长上下文的成本与误差。
   - Lost in the Middle：关键信息埋在中间可能被忽略。
   - 摘要历史、选择片段、结构化上下文、去重裁剪和外部状态保存。
5. 能力来源
   - 语言理解。
   - 代码生成。
   - 推理与工具使用。
   - 模式匹配和泛化的边界。
6. 幻觉与不确定性
   - 模型为什么会编造。
   - 概率生成和事实校验不是一回事。
   - RAG、工具调用和约束输出的作用。
   - 事实性幻觉、推理性幻觉、一致性幻觉。
7. RAG：从实际问题到工程链路
   - 用企业制度问答说明私有知识、知识过期、资料规模、引用和治理问题。
   - 直接询问、塞入全部文档、频繁微调和只做关键词搜索各自为什么不够。
   - 区分适合 RAG 的知识型任务，以及更适合 SQL、业务 API、工具、prompt 或计算器的任务。
   - 参数化知识与外部可更新知识。
   - 解析、去重、切块、元数据、权限和索引版本。
   - 查询理解、改写、分解与可信过滤条件。
   - 关键词、稠密向量、SQL、知识图谱和业务 API 检索。
   - 混合召回、融合、重排和 token 预算内的上下文组装。
   - 证据标签、冲突处理、引用校验与资料不足时拒答。
   - RAG、向量数据库与 Agent 记忆的区别。
8. RAG 评测
   - 评测集中的标准答案、证据、权限、时间和切片信息。
   - 语料、检索、上下文、生成、引用和端到端分层指标。
   - Recall@k、MRR、nDCG、忠实性、引用正确率和拒答准确率。
   - 用检索结果与最终答案的四象限定位故障。
   - 自动评审校准、对抗切片和线上证据链。
9. Prompt 的本质
   - prompt 是设置上下文条件。
   - system prompt 和 user prompt 的区别。
   - 清晰、具体、结构化的 prompt 如何约束生成方向。
   - prompt 仍需要和检索、工具、校验结合。
10. 结构化输出与工具调用
   - JSON/schema 输出为什么重要。
   - Function calling 的基本概念。
   - 模型负责生成参数，系统负责执行和校验。
   - 与 RAG 和 Agent 的关系。

## 实践任务

- 解释 temperature 对输出的影响。
- 设计一个让模型输出 JSON 的 prompt 约束。
- 说明 system prompt 和 user prompt 分别适合放什么。
- 分析一个幻觉案例可能来自哪里。
- 判断企业制度问答、订单查询、退款执行和固定文风分别应优先使用 RAG、业务 API、工具还是 prompt/微调。
- 为一个 RAG 样本定义相关文档、标准答案、引用和拒答条件。
- 为一个企业知识库画出离线入库、在线混合检索和引用校验链路。
- 对比 Recall@k、忠实性和答案正确性，定位检索或生成问题。
- 用同一个 prompt 对比低 temperature 和高 temperature 的输出差异。
- 把关键信息放在上下文不同位置，观察模型是否稳定引用。

## 本章产出

读者应能把 LLM 理解为基于上下文预测 token 的概率模型，而不是全知数据库。
