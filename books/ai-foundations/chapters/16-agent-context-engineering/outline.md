# Agent、工具与上下文工程

## 本章目标

- 采用“实际问题—既有方法的难点—技术机制—适用边界”的叙事顺序，避免核心概念直接从定义起笔。
- 理解 agent 不是单个模型，而是模型、上下文、工具和控制循环组成的系统。
- 理解 harness 的控制面、执行面、状态面和可恢复运行。
- 掌握 MCP、skills、记忆在 agent 架构中的位置。
- 能设计 thread 级短期记忆和跨 thread 长期记忆的读写生命周期。
- 能从模型、harness、上下文、隔离和交付方式比较主流 coding agent。
- 理解“Codex 像实干者、Claude Code 像规划者”是有用的使用模型，而不是绝对能力边界。

## 建议结构

1. Agent 的基本结构
   - 目标、上下文、工具和控制循环。
   - 观察、规划、执行、反馈。
   - 最小 agent 循环伪代码。
   - 用修复类型错误的例子走一遍多轮 agent 循环。
2. Agent Harness
   - Harness 是 agent 的运行外壳，不是模型本身。
   - 控制面、执行面与状态面的分工。
   - queued、running、waiting、retrying、completed、failed 和 cancelled 状态。
   - 检查点、暂停恢复、配置版本与长期等待任务兼容性。
   - 工具 schema、鉴权、审批、幂等、副作用提交和结构化错误。
   - 并发冲突、取消传播、预算与停止条件。
   - 区分上下文、运行状态、记忆、artifact 和 trace。
   - 用类型错误案例走完可恢复、可取消、可验证的运行。
   - MCP、skills、记忆提供能力，harness 负责组织和控制这些能力。
3. Loop Engineering
   - 设计 agent 的多轮执行闭环，而不是优化单次模型回答。
   - 关注继续、停止、重试、换策略、请求确认、回滚和写入记忆等控制规则。
   - 与 harness 的关系：harness 提供执行环境，loop 提供推进任务的控制逻辑。
   - 与 environment engineering 的关系：前者聚焦循环，后者聚焦环境和约束。
4. Agent 与普通工作流的区别
   - 固定流程和开放任务。
   - 灵活性与风险边界。
   - 生产中常见的工作流 + Agent 混合模式。
5. Agent 安全
   - 把外部内容视为不可信数据，模型建议不等于授权。
   - 指令与数据分离、最小临时权限、模型外参数校验。
   - 精确确认、沙箱、幂等、回滚和记忆治理。
   - 直接与间接提示注入、confused deputy、数据外泄和重试副作用。
   - 同时评估正常任务效用与攻击下的安全性。
6. Agent 框架与推理策略
   - LangGraph、CrewAI、AutoGen、OpenAI Agents SDK 和自研 harness。
   - ReAct、Reflexion、Tree-of-Thought。
   - 根据任务状态、权限和生产要求选择框架。
7. MCP
   - 客户端、server 和外部系统。
   - MCP 是开放协议，但不是唯一工具接入方式。
   - tools、resources、prompts。
   - MCP 工具定义示例。
   - 工具抽象、权限和提示注入风险。
8. Skills
   - 可复用任务说明包。
   - 与 MCP 的区别。
   - 粒度和触发条件设计。
   - code review skill 示例。
9. 记忆
   - 短期/长期是生命周期，语义/情景/程序性是内容类型。
   - 短期记忆作为 thread 状态，通过 checkpoint 支持暂停与恢复。
   - 保留窗口、选择性保留、滚动摘要、artifact 外部化和按需重建。
   - 长期记忆的用户、项目、团队、agent 和全局作用域。
   - 记忆记录中的来源、版本、有效期、ACL、敏感性和索引版本。
   - 热路径写入与后台 consolidation。
   - 写入候选、验证、去重、冲突、替代、拒绝与审计。
   - 读取时先做身份与作用域过滤，再做关键词/向量召回和重排。
   - 查看、纠正、删除、过期、缓存与索引传播。
   - 记忆污染、跨租户泄露和删除失效测试。
10. 主流 AI 编程产品
   - 区分基础模型、产品 harness 和交互表面。
   - 从模型、上下文、循环、工具权限、隔离并发和交付六层比较产品。
   - 把 Codex 的任务拆分与并行实现体验概括为“实干者”。
   - 把 Claude Code 的代码库探索、根因分析与计划体验概括为“规划者”。
   - 说明两者都能规划、执行、验证和使用 subagent，个人模型不是永久能力边界。
   - 对比 Codex、Claude Code、GitHub Copilot coding agent、Cursor Agent 和 Gemini CLI／后续终端产品。
   - 解释终端、编辑器、云任务、worktree、issue 和 PR 等协作表面的差异。
   - 用探索、计划、并行、执行、恢复、人机协作、成本与治理建立评测维度。
   - 设计同仓库、同权限、同预算、重复运行的受控产品比较。
   - 通过可验证 artifact 组合不同产品，而不是固定按品牌分配“想”和“做”。
11. 构建 agent 的工程原则
   - 权限边界。
   - 语义化工具。
   - 可控上下文。
   - 可治理记忆。
   - 自动化验证。
12. Agent 的失败模式与轨迹评测
   - 无限循环、上下文溢出、工具误用、过度自信和权限滥用。
   - 目标终态、禁止状态、过程不变量和多条合法路径。
   - 结果、动作、安全、效率与韧性指标。
   - `pass^k` 与 `pass@k` 的区别。
   - 确定性断言、规则、模型评分器和人工复核。
   - Agent trace、环境快照、可重放记录和故障注入。

## 实践任务

- 为一个内部工单处理 agent 画出上下文、工具和权限边界。
- 设计一个 MCP tool schema，说明它为什么比底层 API 更适合给模型使用。
- 为一个重复开发流程写出 skill 的触发条件和步骤。
- 设计一个只读 agent，并写出目标、工具、禁止操作和停止条件。
- 把只读 agent 扩展成可写版本，标出哪些操作必须用户确认。
- 为一个会等待审批的任务设计 run state、检查点和恢复流程。
- 设计短期记忆压缩策略，并说明哪些字段永远不能被普通摘要丢弃。
- 为用户偏好、项目事实和历史案例各设计一条长期记忆记录。
- 为记忆写入设计来源校验、冲突处理、TTL、ACL 和删除流程。
- 为间接提示注入、参数替换、重复副作用和记忆污染设计安全测试。
- 为一项真实任务定义目标终态、禁止状态、过程不变量和轨迹评分表。
- 选择根因 bug、跨模块重构、并行小任务和 UI 迭代四类任务，对两个 coding agent 做受控比较。

## 本章产出

读者应能从系统架构角度理解 agent，设计可恢复的 harness 与可治理的记忆系统，判断问题出在模型、上下文、工具、记忆、状态还是调度层，并能用可复现指标比较和选择主流 coding agent。
